Blueprint access. Instant. Anywhere.

This page lists what Prince of Prints already does today, followed by planned upgrades — focused on real jobsite time savings: from offload to erection, locating tags fast, instant access to cut sheets, and reducing lost time on scrambled paperwork and prints (including damaged, covered, or missing tags).

Receiving (offload) Replace scrambling through a bill of lading with tag-driven locate + checklist tracking.
Erection (field) Click & Fetch from erection sheets directly into cut/detail sheets.
Progress (status) Color-coded piece statuses for fast visual coordination across crews.
Note: Items listed below are planned additions (sync + permissions). Current status tools can be local/exported per job; next step is secure job-scoped syncing.

A Personal Note from the Founder

After 40 years working hands-on in construction, I’ve seen firsthand how much time is lost trying to locate steel that’s missing tags, mis-marked, or simply buried somewhere on site. Those delays add up fast and rarely get counted. 5 iron workers waiting 15 minutes to locate a piece because of a missing tag, equals 1.25 man-hours in lost-time, x 5 days a week equals 6.25 man-hours a week.

This application grew directly out of that frustration. At the very least, it drastically reduces unnecessary trips back to the office or print shack — and anyone who’s worked a muddy jobsite knows how valuable that alone can be.

When iron starts arriving and trucks are stacked up 11 deep waiting to be off-loaded, a true inventory check almost never happens. Verifying every piece against a bill of lading or expected list just isn’t realistic under real jobsite conditions, so material gets staged imperfectly and problems surface later.

The app is intentionally straightforward. Enter a tag ID and it immediately jumps to that piece in the All list. Tap it — checked. Fast and simple. An expediter or forklift operator can stage material efficiently with nothing more than a tablet and a list of tags. If a piece can’t be located, it can be marked yellow directly on the erection drawing.

As work progresses, pieces are marked the same way crews already do on paper prints: pink for rigged, blue for erected, and green for 100% complete. The intent is to keep these controls in the hands of supervisors, with job-scoped locking and syncing planned as a future upgrade.

If a beam sent and turns out to be wrong, it could be a long and costly hunt, but with instant access to cutsheet info, time is saved. no walking, no guessing, no lost time. If it’s the wrong piece, you now have the exact description and specs needed to find the correct one in the pile.

Today, the application runs reliably on mobiles and tablets and supports the core field workflow. Every job’s print set is organized differently, so the focus has been practical automation — tools that generate indexes, but mapping will still have to be done manually for now.

Jobs can be set up either for internet access or for local, offline use. Some crews prefer prints hosted online, while others want everything kept on a jobsite device or shared folder. The application supports both approaches, so each job can be configured to match how the site already operates.

  • Mobile usability refinement — the application currently runs on phones and tablets; continued improvements focus on speed, touch targets, glare/sunlight readability, and glove-friendly interaction.
  • Receiving & inventory workflows — optional checklist-based offload verification tied directly to tags, with clear identification of missing or short material.
  • Job-scoped synchronization — consistent status visibility across devices associated with the same job code, without cross-job data exposure.
  • Supervisor locks & permissions — role-based controls so only authorized foremen or supervisors can apply or change status color codes.
  • Automation tools — utilities to generate indexes, thumbnails, mappings, and job setup artifacts quickly and consistently as print sets vary from job to job.
  • Hardening & reliability — continued testing, performance tuning, and edge-case handling to ensure stability under real jobsite conditions.

Our goal is straightforward: reduce office traffic, reduce wasted man-hours, and give crews a faster way to verify what is on site and what is missing — using the same job code that already scopes access to each job.
